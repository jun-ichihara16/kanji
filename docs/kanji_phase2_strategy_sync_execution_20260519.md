## パート1: 戦略 vs インタビューの差分

結論: **MSH + 再利用幹事率は据え置きでよいが、MSHをそのまま価値到達と見なすのは危険。**  
結論: **現行Top 5のうち、PayPay磨き込みは優先度を下げる。催促レス、後出し費用、デポジットを上げる。**  
結論: **ターゲットは「LINEグループ幹事」より狭く、Excel傾斜・未回収リスク・高頻度幹事に寄せるべき。**

### 1-1. North Star Metric の妥当性

判定: **部分支持。Primary/Companion構造は維持。ただし MSH の品質補助指標が必要。**

現行:

- Primary: MSH = 月間 精算完了幹事数
- Companion: 再利用幹事率 30日 / 60日

支持される点:

- 9人全員が幹事視点で、課題の中心は「幹事が最後までやり切る負担」にある。
- 「集金/支払いリマインド」は9人中4人が期待として言及。
- 「傾斜」は9人中5人が言及し、幹事が会計を完了させる前提課題として強い。
- 「入力面倒」は9人中4人が言及し、初回精算完了率の改善対象として妥当。

修正が必要な点:

- インタビューでは「精算完了したから価値体験」という直接発言はない。
- 逆に「面倒だし気を遣う。自己負担で良いやとなる」「集金が一番ストレス」のように、**自腹で終わらせる精算** が存在する。
- そのため `events.completed_at` だけでは「幹事が損せず完了した」のか「諦めて完了扱いにした」のか分からない。

推奨:

- North Star Pair は維持。
- ただし補助指標として以下を追加する。
  - `unpaid_zero_completion_rate`: 未集金ゼロ精算完了率
  - `host_absorbed_cost_rate`: 幹事自腹化率
  - `settlement_speed_p50`: イベント終了または精算開始から完了までの中央値
  - `post_reminder_completion_rate`: リマインド送信後の支払い完了率

SQL/実装メモ:

- `events.completed_at` は現行計画通り追加。
- 自腹化率は、当面は明示的な「幹事が負担にする」UIがない限り正確に測れない。
- まずは `growth_events` に以下を追加する程度が現実的。
  - `reminder_sent`
  - `manual_reminder_copied`
  - `settlement_marked_paid`
  - `bulk_settle_clicked`
  - `host_absorb_confirmed` ※ UI追加時

ベスプラ示唆:

- Reforge は North Star を単独スコアボードにせず、直接動かせる input metrics と組み合わせる重要性を述べている。KANJIでは MSH がスコアボード、催促レス・精算スピード・未集金ゼロが input/quality metrics に相当する。[^reforge]
- CRV は seed では retention と定性シグナルが重要で、単一閾値よりコホートや文脈を見るべきとしている。再利用幹事率と定性サイン併用はこの方向に合う。[^crv]

### 1-3. ターゲット定義の精度向上

現状:

- 20〜30代の幹事 / LINEグループ運営層

修正版:

1. **Excel傾斜計算の社会人幹事**
   - 20代後半〜30代中心 ※推測
   - 社内飲み、同窓会、サークルで年複数回幹事
   - 年齢、役職、男女、飲量の傾斜を毎回考える
   - 代表根拠: ばん、扇山、ケンティ、せいしろう、りょう

2. **大型イベント/コミュニティ運営の半プロ幹事**
   - クラブイベント、BBQ、大人数飲み会
   - 直前キャンセル、箱代、未集金が直接損失
   - 代表根拠: 中村、やな、えな

3. **ドライブ/旅行系の後出し精算幹事**
   - ETC、高速代、ガソリン代、ドライバー割引
   - 後で思い出す費用が多い
   - 代表根拠: りょう、せいしろう、ばん

価値を感じにくいセグメント:

- 少人数でPayPay統一済みの固定グループ
- LINE公式アカウント登録に抵抗が強い層
- PayPayに大金を入れること自体に抵抗がある層
- 参加者視点のみの人は未検証

参加者→幹事化の典型像:

- 直接データなし。
- ※推測: 共同幹事/招待リレーを体験し、「これなら自分でも回せる」と感じる参加者。
- 参加者インタビューがゼロのため、T-305で必須検証。

### 1-4. Gate 通過判定

判定: **現行Gateは大枠維持。ただし質的Gateに「催促レス/自腹ゼロ」条件を足す。**

現行:

- Gate 0: 計測基盤稼働
- Gate 1: 定性サイン3つ
- Gate 2: MSH 3ヶ月移動平均30以上、再利用幹事率60日25%以上、K-factor 0.1以上等

修正案:

- Gate 0は据え置き。
- Gate 1に以下を追加。
  - 3人以上が「催促が楽になった」と明示
  - 1人以上が「自腹を避けられた」と明示
  - 手動リマインドまたはテンプレ利用が実イベントで発生
- Gate 2に以下を補助条件として追加。
  - `post_reminder_completion_rate` が継続的に改善
  - `settlement_speed_p50` が短縮
  - `host_absorbed_cost_rate` が計測可能になっている、または定性で自腹回避が確認できる

MSH 50/月について:

- 現行 `01_strategy.md` では早期前倒し条件として MSH 50/月、通常Gate 2は3ヶ月移動平均30以上。
- 9件のインタビューだけでは、数値ラインを上げ下げする根拠は不足。
- したがって数値は据え置き、質的条件を補強するのが妥当。

## パート2: 戦略修正案

結論: **`01_strategy.md` は v1.2 として、催促レス設計への優先順位変更を追記する。**

結論: **Phase 2でやらないことに、飲食店連携・ポイント・本格OCR・自動デポジット徴収を明記する。**

### 2-1. 修正版「戦略サマリー」

North Star:

- Primary: MSH = 月間 精算完了幹事数
- Companion: 再利用幹事率 30日 / 60日
- Quality Metrics:
  - 未集金ゼロ精算完了率
  - 自腹ゼロ達成率
  - 精算スピード

優先施策 Top 5:

Gate:

### 2-3. Phase 2でやらないこと

やらない:

- 飲食店連携
  - 店選びやお店DB要望はあるが、Phase 2のPMF検証軸から外れる。
- ポイント機能
  - Phase 3マター。インタビューでも前倒しすべき強い根拠なし。
- 本格レシートOCR
  - 飯島の要望はあるが1人。実装コストが高い。
- 自動デポジット決済
  - やな・ばんの示唆は強いが、決済/返金/キャンセル規約が重い。
- LINE自動Pushリマインドの本格運用
  - 参加者側の受け止め未検証。まず手動テンプレでよい。
- 席決め/アレルギー回収
  - えなの会社飲み会要望として有望だが、会計PMFから逸れる。

### 3-2. 「Phase 2 計測基盤」より優先すべきもの

大規模なUX改修を先にする必要はない。

理由:

- インタビュー結果は「何が痛いか」は示すが、KANJI実利用でどこが離脱しているかは未計測。
- 現在の最大リスクは、施策を打っても MSH / 再利用 / K-factor に効いたか分からないこと。
- ただし「催促文面テンプレ」は実装軽量で、催促レス仮説の初期検証に使えるため並走可。

計測基盤より先にやってよいもの:

- 催促文面テンプレ
- 未払い者一覧の表示改善
- LINE共有文面の改善

先にやらないもの:

- 自動Pushリマインド
- OCR
- 事前決済/デポジット本実装
- 飲食店DB
- ポイント

### 3-3. T-305 実利用者ヒアリングの位置付け

判断: **実装と並行。追加3名だけは早急に実施。**
