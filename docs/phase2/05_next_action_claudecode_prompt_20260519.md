# KANJI Phase 2 次アクション手順 + Claude Code 向けプロンプト

作成日: 2026-05-19  
目的: インタビュー結果を反映した Phase 2 計画へ更新し、計測基盤から実装に入るための実行手順を明確にする。

---

## 結論

次は、いきなり実装ではなく **Phase 2 戦略の改訂 → Week 0 プライバシー確認 → Week 1-2 計測基盤実装 → 催促レス施策実装** の順で進める。

現行の Phase 2 戦略は「立替登録の谷」を主ボトルネックにしているが、インタビュー整理レポートでは「催促・未回収・自腹化」の心理コストがより強く出ている。したがって、Phase 2 の旗印を **催促レス設計** に寄せる。

---

## 具体的な手順

### Step 1. 戦略文書を改訂する

対象:

- `docs/phase2/01_strategy.md`
- 必要なら `docs/phase2/04_decision_log.md`

やること:

- インタビュー結果を反映した改訂履歴を追加する
- 最大ボトルネックを「立替登録の谷」から「催促・未回収・自腹化の心理コスト」へ再評価する
- 優先施策 Top 5 を「催促レス設計」中心に組み替える
- MSH / 再利用幹事率は維持しつつ、補助指標に以下を追加または明記する
  - 精算スピード
  - 未集金ゼロ達成
  - 自腹ゼロ達成
  - リマインド送信後の支払い完了率
- データ品質の注意点を明記する
  - 9件のみ
  - KANJI実利用評価が弱い
  - 参加者視点が欠落
  - 属性情報が不足

完了条件:

- `01_strategy.md` を読むだけで「なぜ催促レス優先になったか」が追える
- 旧戦略を全否定せず、インタビューによる優先順位変更として説明されている

---

### Step 2. 実装計画への影響を整理する

対象:

- `docs/phase2/02_implementation_plan.md`
- 必要なら新規メモ `docs/phase2/06_phase2_revised_implementation_notes.md`

やること:

- 既存の計測基盤実装は維持する
- ただし、催促レス施策に必要なイベントログを追加検討する
  - reminder_sent
  - reminder_clicked
  - settlement_marked_paid
  - settlement_completed_after_reminder
  - host_absorbed_cost または unpaid_amount_zeroed など、自腹化の検知に使えるログ
- 実装順を以下に再整理する
  - Week 0: プライバシー・同意・削除運用
  - Week 1: `completed_at` / MSH / 集計クエリ
  - Week 2: 招待トラッキング / Admin KPI
  - Week 3以降: 催促レス施策

完了条件:

- 実装者が「まず何を作るか」で迷わない
- DB変更とUI施策が混ざらず、計測基盤が先に切り出されている

---

### Step 3. Week 0 を先に片付ける

対象:

- `docs/phase2/03_privacy_policy.md`
- アプリ側のオンボーディング/設定画面

やること:

- Phase 2 計測で取得するデータを明文化する
- 同意UIの有無を確認する
- 削除依頼時の運用を確認する
- RLSポリシー変更が必要な場合は、実装前に必ずユーザー確認を取る

完了条件:

- 計測基盤の実装前に、取得データ・保持期間・削除運用が説明できる

---

### Step 4. 計測基盤を実装する

対象:

- `app/supabase/migrations/`
- `app/src/lib/`
- `app/src/pages/admin/`
- Edge Functions が関係する場合は `app/supabase/functions/`

やること:

- `events.completed_at` の追加
- 精算完了時に `completed_at` を初回のみ記録
- MSH 集計クエリ
- 再利用幹事率集計
- K-factor / 招待トラッキング
- Admin dashboard で最低限の確認UI

完了条件:

- ローカルテストで MSH 相当の値が確認できる
- 既存の精算フローが壊れていない
- `npm run test` と `npm run build` が通る

---

### Step 5. 催促レス施策を小さく出す

最初の実装候補:

1. 支払い状況の見える化
2. 共有・催促文面テンプレ
3. 手動リマインド送信
4. 自動リマインド
5. 後出し費用対応

優先順位:

- まずは自動化よりも、幹事が「誰が未払いか」「何を送ればいいか」を迷わない状態を作る
- LINE Messaging API による自動送信は、手動テンプレの利用状況を見てからでよい

完了条件:

- 幹事が催促文を自分で考えなくて済む
- 未払い者の把握が一目でできる
- リマインド後に支払い完了したかを追える

---

### Step 6. 追加インタビューを並走する

対象:

- KANJI実利用者
- 途中離脱者
- 参加者のみで幹事未経験の人

確認したいこと:

- 催促が本当に最大ペインか
- 事前デポジットへの抵抗感
- 自動リマインドが失礼に見えない条件
- LINE公式アカウント登録の障壁
- 参加者が幹事化するきっかけ

完了条件:

- 「催促レス設計」が仮説ではなく、次の施策判断に使える程度に裏取りされている

---
